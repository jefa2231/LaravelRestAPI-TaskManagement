REST / URL kata benda, method kata kerja 08

Satu sumber daya, lima operasi standar.

MethodEndpointArtiSukses
GET /api/v1/surat?status=diajukan&page=2 Daftar surat, filter + halaman 200
GET /api/v1/surat/4 Detail satu surat 200
POST /api/v1/surat Ajukan surat baru 201
PATCH /api/v1/surat/4/status Ubah status saja 200
DELETE /api/v1/surat/4 Hapus surat 204
GET /api/v1/jenis-surat Pilihan dropdown 200
Hindari gaya RPC

POST /api.php?action=hapus&id=4 menyembunyikan operasi di dalam body. URL-nya tidak bisa ditebak tanpa membaca dokumentasi.

Versi di URL

/v1 memberi ruang untuk perubahan besar tanpa mematahkan client lama. Perubahan kecil yang kompatibel tidak perlu versi baru.

KONSISTENSI

Semua daftar memakai paginasi, semua detail memakai amplop data, semua error memakai message + errors.

Kata benda

Resource selalu jamak: /surat, /mahasiswa. Bukan /getSurat.

Kata kerja

Method menentukan aksi. Satu URL yang sama melayani baca, ubah, dan hapus.

Status code / hasil yang bisa dibaca mesin 09

Status code memberi tahu hasilnya sebelum body dibaca.

Berhasil
200OK — ada data yang dikembalikan
201Created — POST berhasil, ada Location
202Accepted — diterima, diproses belakangan
204No Content — DELETE berhasil, tanpa body
Gagal
400Bad Request — body bukan JSON valid
401Unauthorized — kunci tidak ada atau salah
403Forbidden — dikenali, tetapi tidak berhak
404Not Found — data atau endpoint tidak ada
422Unprocessable — validasi gagal
500Server Error — bug di server, bukan salah client
Aturan emas

Jangan membalas error dengan 200 + {"ok": false}. fetch, Postman, dan monitoring membaca status code. Kalau semuanya 200, kegagalan tidak terlihat sampai seseorang membuka body.

Kontrak data / delapan aturan 11

Format yang konsisten lebih penting daripada format yang canggih.

01

snake_case dan konsisten: status_label, dibuat_pada, bukan campuran gaya.

02

ISO 8601 dengan zona waktu: 2026-09-20T15:45:00+07:00. Frontend yang memformat tampilan.

03

Status sebagai kode string: "diajukan". Label tampilan dikirim terpisah.

04

NIM dan nomor HP berupa string, bukan number. Bisa diawali nol dan tidak untuk dihitung.

05

Kosong berarti null, bukan string kosong atau field yang hilang tanpa alasan.

06

Bungkus dengan data. Info tambahan di meta dan links.

07

Jangan kirim kolom rahasia atau data berlebih. Password, token, dan catatan internal tidak pernah masuk respons.

08

Server boleh mengirim petunjuk UI, seperti aksi_berikutnya, agar aturan bisnis tidak diduplikasi di frontend.

Konsekuensinya

Frontend cukup menulis satu lapisan API. Setiap backend baru mengikuti kontrak yang sama, tidak ada kode UI yang berubah.

tidak konsistenJSON
{
  "statusLabel": "Diajukan",

  "NIM": 2201004
}
konsistenJSON
{
  "status_label": "Diajukan",
  "dibuat_pada": "2026-09-20T15:45:00+07:00",
  "nim": "2201004"
}

Daftar / paginasi 13

Daftar tidak pernah dikirim seluruhnya.

Kenapa dibatasi

Sepuluh ribu surat berarti sepuluh ribu objek di memori server, di jaringan, dan di browser. Satu permintaan yang lambat terasa seperti aplikasi rusak.

Ikuti links.next

Jangan menebak jumlah halaman. Client membaca links.next sampai null.

Batasi per_page

Maksimum 50. Tanpa batas, satu permintaan bisa meminta seluruh isi penyimpanan.

META

Memuat current_page, last_page, per_page, dan total.

GET /api/v1/surat?per_page=2 → 200JSON

400 · body rusak

{"message": "Body request bukan JSON yang valid."}

Kunci errors = nama field

Frontend menempelkan pesan tepat di bawah input yang salah tanpa kode khusus per field.

Detail 500 hanya di log

Client menerima pesan umum. Stack trace tidak pernah dikirim ke luar.

Laravel: format ini sudah bawaan. ValidationException menghasilkan 422 dengan errors per field.

Node.js: bentuk yang sama dibuat manual di errorHandler, supaya frontend tidak peduli backend-nya.
