01 / PERAN

Menjelaskan API sebagai jembatan

Kenapa dua sistem memilih bertukar data lewat HTTP, bukan saling membuka database.

Method, URL, header, body, dan status code. Lima bagian yang selalu ada.

Webhook, HTTP client dengan timeout, paginasi, CORS, lalu konsumsi dari UI.

Masalah / konteks kampus 03

Empat aplikasi, satu data, nol cara untuk saling bicara.

Setiap tim membangun sistemnya sendiri. Datanya sama, tetapi tidak ada pintu resmi untuk mengambil atau mengirimnya.

SIAKAD

PHP · Laravel

Menyimpan surat, mahasiswa, dan status.

NOTIFIKASI

Node.js

Mengirim WhatsApp dan email.

MOBILE

Flutter · Kotlin

Butuh daftar surat milik mahasiswa.

PIMPINAN

React

Butuh rekap dan statistik harian.

Kalau dipaksa tanpa API

  • Setiap tim meminta akses langsung ke database orang lain.
  • Satu perubahan skema mematahkan empat aplikasi sekaligus.
  • Tidak ada batas siapa boleh membaca apa.
AKIBATNYA

Integrasi jadi proyek khusus, bukan hal biasa.

Setiap pasangan sistem butuh kesepakatan sendiri. Biaya integrasi tumbuh lebih cepat daripada jumlah sistemnya.

Solusi / apa yang sebenarnya disepakati 04

Kontrak, bukan teknologi.

API adalah pintu resmi berupa URL yang menerima dan mengirim data dalam format yang disepakati. Yang disepakati bukan bahasa pemrogramannya, melainkan perilakunya.

Analogi

Pelanggan tidak masuk dapur. Ia memesan lewat menu, pelayan membawakan hasilnya. Menu itu kontrak: nama hidangan, bahan, harga, dan apa yang terjadi kalau pesanannya salah.
